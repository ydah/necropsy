# ADR-0004: No generic template format parsers

Status: No-go
Date: 2026-08-12
Legacy-ID: #81, #90, #95
Review-items: #81, #90, #95
Superseded-by: None

## Context

Haml, Slim, Jbuilder, Builder, YAML, JSON, TOML, GraphQL SDL, SQL, and
OpenAPI do not share a sound notion of a Ruby method reference. Generic token
extraction would create negative evidence without a reviewed grammar. A
`trusted_generated` bypass would likewise convert provenance into permission to
ignore runtime callbacks.

## Decision

Necropsy does not pretend to parse those formats generically. The reference
barrier may add scoped or global blockers and degraded health when input is
unreadable, oversized, generated, or budget-exhausted. ERB is the explicit
exception: executable Ruby regions are extracted and parsed with Prism. Format-
aware context and qualified-owner matching may reduce noise, but they do not
claim complete parsing or authorize a generated-file bypass.

## Consequences

Some valid references remain blockers until a format-specific contract exists.
This preserves safety at the cost of fewer removal candidates. A project can
declare actual hooks through configured entry points instead of relying on a
generic presenter or template convention; see [ADR-0005](0005-no-generic-presenter-convention.md)
for the presenter boundary.

## Reconsideration gate

Consider a format adapter only after at least two reviewed corpora provide a
versioned grammar/conformance suite with zero known-positive false negatives.
Consider a generated bypass only when the producing input is scanned and a
content-addressed derivation proves reference equivalence for every fixture.
