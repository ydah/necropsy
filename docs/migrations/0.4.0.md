# Migration guide: 0.4.0

> Status: Unreleased

This guide describes the changes planned for the unreleased 0.4.0 line.

Custom analyzers execute Ruby code in the Necropsy process. They must now use a mapping with an explicit trust declaration:

```yaml
analyzers:
  custom:
    - class: Company::Analyzer
      require: config/company_analyzer.rb
      trusted: true
```

The former string form is rejected. `trusted: true` means that the analyzer and its required file are allowed to execute with the same privileges as Necropsy; it does not weaken result validation or atomic result application.

## Actionability and CI thresholds

Reports now distinguish `priority_score`/`confidence` from `reachability_state`,
`analysis_completeness`, and `actionability`. A blocker always keeps a finding
diagnostic, even when its priority score is high. The default `ci.fail_on` is
now `new_review_candidate`; existing `high`, `certain`, and other confidence
values continue to work as compatibility thresholds, but should be migrated
to an actionability threshold for deletion gates.

Run `necropsy doctor` after migration to find confidence-based gates, incomplete
analysis, narrowed scopes, and unrooted load units.

## New workflow commands

`feedback compare`, `feedback export-fixtures`, and `feedback verify` consume a
graph report plus positive runtime target observations. Missing static targets
are safety regressions; unobserved static targets remain informational.

`diff --base old.json --head new.json` compares physical definitions and reports
newly unreachable/blocked/reachable transitions, resolution changes, health
changes, and the last incoming edge. `plan`, `patch`, and `verify` consume a
report and a physical candidate ID; verification edits only a temporary copy.
